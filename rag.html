1. Vector Databases & Indexing

Production vector engines (Pinecone, ChromaDB, Qdrant, Weaviate, pgvector) don't run brute-force O(N) cosine checks on millions of vectors. They construct Approximate Nearest Neighbor (ANN) graphs such as HNSW (Hierarchical Navigable Small World) to achieve sub-10ms search latency.

  • HNSW: Ultra-fast search, higher RAM usage.
  • IVFFlat: Inverted file clusters, low memory footprint.

2. Advanced Retrieval & Re-ranking

Naive vector search can miss keywords or retrieve semantically similar but legally irrelevant text. Modern production RAG employs Hybrid Search (Dense embeddings + Sparse BM25) followed by a Cross-Encoder Re-ranker (like Cohere Rerank or BGE-Reranker-Large) to re-score candidates.

  • Sparse (BM25): Catches exact IDs, SKUs, and proper nouns.
  • Cross-Encoder: Evaluates Query + Chunk jointly.

3. Mitigating LLM Hallucinations

LLMs generate confident falsehoods when missing domain context. RAG transforms the model from a generative guesser into a grounded reader-evaluator. Strict system prompting instructs the model to refuse answering if the retrieved chunk threshold is not met.

  • Faithfulness Evaluation: TruLens, Ragas metrics.
  • Lost-in-the-Middle: Prioritizing chunks at ends of prompt.
